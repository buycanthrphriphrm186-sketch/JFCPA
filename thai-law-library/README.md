# THAI LAW LIBRARY — คลังกฎหมาย

ระบบมี 2 ไฟล์แยกกัน:

| ไฟล์ | วางที่ไหนใน Apps Script |
|---|---|
| `Code.gs` | ไฟล์สคริปต์ชื่อ **Code.gs** (รหัส GS เท่านั้น) |
| `Index.html` | ไฟล์ HTML ชื่อ **Index** (กด + > HTML > ตั้งชื่อ `Index`) |

> ข้อผิดพลาด `SyntaxError: Invalid regular expression: missing /` ที่เคยเกิด
> มาจากอักขระที่มองไม่เห็น (U+2028) ในโค้ด หรือการวางโค้ด HTML ลงใน Code.gs
> ไฟล์ชุดนี้ตรวจแล้วว่าไม่มีอักขระดังกล่าว และผ่านการตรวจไวยากรณ์ทั้งสองไฟล์

## ติดตั้ง (ครั้งเดียว)

1. เปิด https://script.google.com สร้างโปรเจกต์ใหม่ (หรือ ส่วนขยาย > Apps Script จาก Google Sheets)
2. ลบโค้ดเดิมใน Code.gs ทั้งหมด แล้ววางเนื้อหา `Code.gs`
3. สร้างไฟล์ HTML ชื่อ `Index` แล้ววางเนื้อหา `Index.html`
4. เลือกฟังก์ชัน `setup` แล้วกด **Run** และอนุญาตสิทธิ์
   ระบบจะสร้างชีตทั้งหมดใน Google Sheets `1Pddk_3GswY2_kuSzuNGIP6KVBeeBnGOHcGCqUvag-7E`
   และนำข้อมูลกฎหมาย/อนุสัญญาลงชีตให้
5. **Deploy > New deployment > Web app** — Execute as: **Me**, Who has access: **Anyone**
6. เปิด URL ที่ลงท้าย `/exec`

ทุกครั้งที่แก้โค้ด ต้อง Deploy > Manage deployments > แก้ไข > Version: New version
(ถ้าเวอร์ชันใหม่มีปัญหา เลือกเวอร์ชันก่อนหน้าในหน้าเดียวกันเพื่อย้อนกลับทันที)

## ฐานข้อมูลกฎหมาย (นำเข้าอัตโนมัติหลังรัน setup)

ตัวบทกฎหมายไทยไม่มีลิขสิทธิ์ (พ.ร.บ.ลิขสิทธิ์ พ.ศ. 2537 มาตรา 7) ฐานข้อมูลในโฟลเดอร์ `db/` รวบรวมจากชุดข้อมูลเปิด 3 แหล่ง
ที่อนุญาตให้นำไปใช้ต่อได้ และระบุที่มา/สัญญาอนุญาตไว้กับกฎหมายทุกฉบับ (แสดงในหน้าเว็บด้วย)

| ลำดับ | แหล่ง | สัญญาอนุญาต | ใช้สำหรับ |
|---|---|---|---|
| 1 | [NitiBench-statute](https://huggingface.co/datasets/VISAI-AI/nitibench-statute) (VISTEC/VISAI) | MIT | ตัวบทฉบับปรับปรุง เช่น ป.พ.พ. (1,842 มาตรา), ประมวลรัษฎากร |
| 2 | [OCS Krisdika](https://huggingface.co/datasets/Surathai21/ocs-krisdika) — Open Law Data Thailand (ข้อมูลต้นทาง: สำนักงานคณะกรรมการกฤษฎีกา) | CC-BY-4.0 | รัฐธรรมนูญ 2560, ป.อ., ป.วิ.พ., ป.วิ.อ., พ.ร.ป. และพระราชบัญญัติส่วนใหญ่ |
| 3 | [thailaw-v1.0](https://huggingface.co/datasets/pythainlp/thailaw-v1.0) (PyThaiNLP) | CC0-1.0 | พระราชบัญญัติ/ประกาศที่ไม่มีในแหล่งอื่น |

ผลรวม: กฎหมาย 4,304 ฉบับ / 118,803 มาตรา (รัฐธรรมนูญ 10, พ.ร.ป. 26, พ.ร.บ./พ.ร.ก. 3,620, ปร./ปว./คปค./คสช. 640, ประมวลกฎหมาย 8)

- `setup` ตั้งเวลา `importTick` ทุก 10 นาที: ดึง `db/*.json.gz` จาก GitHub ของโครงการ (แหล่งหลัก) จนครบ
  หากเชื่อมต่อไม่ได้จะสลับไปนำเข้าจาก Hugging Face (แหล่งสำรอง) อัตโนมัติ ความคืบหน้าดูที่ชีต `Config` คีย์ `IMPORT_STATUS`
  และในหน้า "ความช่วยเหลือ" ของเว็บไซต์
- เปลี่ยนที่อยู่ฐานข้อมูลได้ที่ Script Property `DB_BASE_URL` (เช่น เมื่อ merge เข้า main ให้เปลี่ยน branch ใน URL)
- ข้อจำกัดของแหล่งข้อมูล: ป.วิ.พ. และ ป.วิ.อ. ในชุดข้อมูลกฤษฎีกาเป็นฉบับก่อนการแก้ไขเพิ่มเติมบางครั้ง ระบบจึงแสดงสถานะ
  "โปรดตรวจสอบการแก้ไขเพิ่มเติมกับต้นฉบับ" ไว้ที่กฎหมายนั้น และรัฐธรรมนูญ พ.ศ. 2475–2502, 2534, 2557 ยังไม่มีในชุดข้อมูลเปิด
- สร้างฐานข้อมูลใหม่: สคริปต์ build อยู่ใน `tools/build-db.js` (ต้องดาวน์โหลดชุดข้อมูลทั้ง 3 แหล่งก่อน)

## ผู้ดูแลระบบ

- ตั้งตัวเองเป็นผู้ดูแล: ในชีต `Members` ใส่ `admin` ที่คอลัมน์ `role`
- ชีต `Config`: เปิด/ปิดฟีเจอร์ (`FLAG_*`), ปิดปรับปรุง (`MAINTENANCE`=on), ย้อนกลับฉุกเฉิน (`FORCE_SAFE_MODE`=on), เวลาโลโก้ (`SPLASH_SECONDS`)
- เปิดสิทธิ์แพ็กเกจ: แก้สถานะในชีต `Payments` เป็น `ชำระแล้ว` แล้วรันฟังก์ชัน `activatePaidPlans`
- ออกรหัสผ่านชั้นที่ 1 เฉพาะบุคคล / ปลดล็อกบัญชี: เมนู THAI LAW LIBRARY ในชีต
- เพิ่มตัวบทกฎหมาย: เพิ่มแถวในชีต `Sections` (lawId, sectionNo, popularName, text) แล้วหน้าเว็บจะแสดงเอง

## เวอร์ชัน 4 — สิ่งที่เพิ่ม

- **รหัสผ่าน 3 ชั้น**: ชั้น 1 รหัสจากผู้ดูแลระบบ → ชั้น 3 รหัสผ่านส่วนตัว → ชั้น 2 รหัส 6 หลักที่ส่งไปยังอีเมลของสมาชิกทุกครั้ง (หมดอายุ 10 นาที ผิดได้ 5 ครั้ง)
  ส่งด้วย MailApp ของบัญชีเจ้าของสคริปต์ (โควตา Gmail ทั่วไปประมาณ 100 ฉบับ/วัน) — สมาชิกเดิมที่ยังไม่มีอีเมลจะถูกขอให้กรอกอีเมลตอนเข้าสู่ระบบ

- สถิติผู้เข้าชม (ชีต `Stats` + หน้า `สรุปผล` พร้อมกราฟ) และแดชบอร์ดบนหน้าแรก, GA4 ใส่รหัส `G-XXXX` ที่ชีต `Config` คีย์ `GA4_ID`
- กฎหมายต่างประเทศ: ญี่ปุ่น (e-Gov API ทางการ) อ่านได้ในเว็บไซต์, เกาหลีเมื่อใส่ `KOREA_OC`, ประเทศอื่นแสดงลิงก์แหล่งทางการ (ไม่มี API ที่อนุญาต)
- PDF ทางการ: ประวัติการเข้าสู่ระบบ, สำรองข้อมูล, ข้อมูลสมาชิก — ประวัติการเข้าสู่ระบบลบอัตโนมัติเมื่อครบ 90 วัน
- จัดรูปแบบชีต 4 สี (ฟ้า เขียว ขาว ดำ): เมนู THAI LAW LIBRARY > จัดรูปแบบชีตและหน้าสรุปผล

## เผยแพร่ผ่าน Vercel (ลิงก์สาธารณะ)

โฟลเดอร์ `vercel/` เป็นหน้าเว็บที่ห่อ Apps Script Web App ไว้ (ชื่อเว็บ โลโก้ favicon และส่วนหัวความปลอดภัย) — ตัวระบบหลังบ้านยังเป็น Code.gs + Google Sheets เหมือนเดิม

1. Deploy Apps Script เป็น Web app แล้วคัดลอก URL ที่ลงท้าย `/exec`
2. แก้ไฟล์ `vercel/config.js` ใส่ `window.TLL_APP_URL = 'https://script.google.com/macros/s/.../exec';` แล้ว commit
3. ที่ https://vercel.com/new เลือก Import repository `JFCPA` → Root Directory: `thai-law-library/vercel` → Framework: Other → Deploy
4. ได้ลิงก์ `https://<ชื่อโปรเจกต์>.vercel.app` (ตั้งชื่อโดเมนเองได้ใน Settings > Domains)

ข้อจำกัด: การเข้าสู่ระบบด้วย Google/Apple/Facebook/LINE ไม่ทำงานภายในกรอบ (iframe) ตามนโยบายของผู้ให้บริการ ระบบจะใช้การเข้าสู่ระบบด้วยรหัสผ่าน 3 ชั้นได้ตามปกติ

### การแจ้งเตือนการสมัครสมาชิกใหม่
- ส่งอีเมลถึงผู้ดูแลทุกครั้ง (ค่าเริ่มต้น `thailawlibrary.official@gmail.com` หรือ Script Property `ADMIN_EMAIL`) — ข้อมูลทุกช่องที่ผู้สมัครกรอก **ยกเว้นรหัสผ่านและคำตอบกู้คืนบัญชี** (เก็บเป็นค่าแฮช ไม่ส่งออกนอกระบบ)
- ส่งไปยังปลายทางภายนอกด้วยรหัส API/Token: ใส่ Script Properties
  - `NOTIFY_TOKEN` = รหัส Token ที่ได้รับ
  - `NOTIFY_URL` = URL ปลายทางของบริการนั้น (รองรับ Telegram `https://api.telegram.org/bot<TOKEN>/sendMessage` + `NOTIFY_CHAT_ID`, Discord/Slack webhook, ntfy หรือ webhook ใดก็ได้ที่รับ JSON — ระบบส่ง `Authorization: Bearer <NOTIFY_TOKEN>`)
- ไม่บันทึก Token ไว้ในโค้ด (คลังโค้ดเป็นสาธารณะ)

## เวอร์ชัน 7 — แจ้งเตือนการสมัครสมาชิกใหม่ทาง LINE

เพิ่มต่อจากเวอร์ชัน 6 โดยไม่เปลี่ยนการทำงานเดิม: อีเมลถึงผู้ดูแลและ `NOTIFY_URL` ยังส่งเหมือนเดิม และมีการส่งทาง LINE เพิ่มเข้ามา

### วิธีอัปเกรด
1. วาง `Code.gs` และ `Index.html` ใหม่ทับไฟล์เดิม แล้วกดบันทึก
2. ไปที่ Project Settings › Script Properties › Add script property แล้วเพิ่มค่าเหล่านี้
   - `LINE_CHANNEL_TOKEN` = รหัส Channel access token ของ LINE OA (รหัสยาวที่ลงท้ายด้วย `=`)
     - **ห้ามใส่รหัสนี้ไว้ในโค้ด** เพราะคลังโค้ดเป็นสาธารณะ
   - `LINE_TO` (แนะนำ) = User ID ของผู้รับแจ้งเตือน
     - หาได้ที่ LINE Developers › Channel › Basic settings › **Your user ID** (ขึ้นต้นด้วย `U`)
     - ใส่ได้หลายรายการ ให้คั่นด้วยจุลภาค
     - ใช้ Group ID (ขึ้นต้นด้วย `C`) ได้ด้วย
3. ไปที่ Deploy › Manage deployments › แก้ไข › Version: **New version** แล้วกด Deploy
   - URL `/exec` เดิมยังใช้ได้
   - ระบบจะอัปเกรดตัวเองเป็นเวอร์ชัน 7.0.0 ข้อมูลเดิมยังอยู่ครบ
4. ทดสอบการส่ง
   - ในตัวแก้ไขสคริปต์ เลือกฟังก์ชัน `testLineNotify` แล้วกด Run
   - ข้อความทดสอบจะส่งไปที่ LINE

### การทำงาน
- **เมื่อส่ง:** ทันทีที่ผู้ใช้กดยืนยันการสมัครและสมัครสำเร็จ
- **รูปแบบข้อความ:** ข้อความ Flex มีหัวข้อ “แจ้งเตือนการสมัครใช้งานบัญชีใหม่ — ระบบ “คลังกฎหมาย”” ตามด้วย
  - ตารางข้อมูลทุกช่องที่ผู้สมัครกรอก
  - วันและเวลาที่สมัคร
  - ปุ่มเปิดเว็บไซต์
- **ข้อมูลที่ไม่ส่ง:** รหัสผ่านทั้ง 3 ชั้นและคำตอบกู้คืนบัญชีจะไม่ถูกส่งเด็ดขาด
- **ปลายทาง:** ข้อความส่งแบบ push ถึงผู้รับใน `LINE_TO`
  - ถ้ายังไม่ได้ตั้ง `LINE_TO` ระบบจะส่งแบบ broadcast ถึงเพื่อนของ LINE OA ทุกคน
  - ในแบบ broadcast ระบบจะตัดอีเมล เบอร์โทร ที่อยู่ และวันเกิดออก (ข้อมูลเหล่านี้ยังส่งทางอีเมลผู้ดูแล)
- **เมื่อส่งไม่สำเร็จ:**
  - ระบบจะลองส่งใหม่ 1 ครั้ง (มี `X-Line-Retry-Key` จึงไม่มีข้อความซ้ำ)
  - ถ้า LINE ไม่รับข้อความ Flex ระบบจะส่งเป็นข้อความธรรมดาแทน
  - ถ้ายังส่งไม่ได้ ระบบจะบันทึกลงชีต ErrorLog
  - **การสมัครยังสำเร็จตามปกติเสมอ**

### จับคู่ผู้รับอัตโนมัติ (ไม่บังคับ)
1. ใน LINE Developers › Messaging API › Webhook URL ให้ใส่ลิงก์ `/exec` ของเว็บไซต์ แล้วเปิด Use webhook
   - ปุ่ม Verify อาจแสดง 302 ซึ่งเป็นพฤติกรรมปกติของ Apps Script ระบบยังรับข้อความได้
2. ส่งข้อความ `เชื่อมต่อ <รหัสจับคู่>` หา LINE OA
   - รหัสจับคู่ส่งไปทางอีเมลผู้ดูแลเมื่ออัปเกรด
   - ดูรหัสได้อีกทางใน Log ของ `testLineNotify`
3. ระบบเพิ่มผู้ส่งเข้า `LINE_TO` ให้เอง
   - รหัสจับคู่ใช้ได้ครั้งเดียว
   - ถ้าใส่รหัสผิด 5 ครั้ง ระบบจะหยุดรับ 1 ชั่วโมงและแจ้งผู้ดูแลทางอีเมล

## เวอร์ชัน 8 — LINE รายสมาชิก (ยืนยันด้วยเบอร์โทรศัพท์) + ประมวลกฎหมายหลักฉบับปรับปรุง + จำนวนกฎหมายตามข้อเท็จจริง

### วิธีอัปเกรด
1. วาง `Code.gs` และ `Index.html` ใหม่ทับไฟล์เดิม แล้วไปที่ Deploy › Manage deployments › แก้ไข › Version: **New version** แล้วกด Deploy
   - URL `/exec` เดิมยังใช้ได้
   - ระบบจะอัปเกรดเป็นเวอร์ชัน 8.0.0 เอง
   - ข้อมูลสมาชิกเดิมยังอยู่ครบ
   - ชีตสมาชิกจะมีคอลัมน์ใหม่ “LINE User ID” และ “เชื่อมต่อ LINE เมื่อ”
2. ไปที่ Script Properties แล้วใส่ `LINE_CHANNEL_TOKEN` (ถ้ายังไม่ได้ใส่ตั้งแต่เวอร์ชัน 7)
3. ไปที่ LINE Developers › Channel › Messaging API › **Use webhook** แล้วกดเปิด
   - Webhook URL ตั้งเป็นลิงก์ `/exec` ของเว็บไซต์ไว้แล้ว
   - ปุ่ม Verify อาจแสดงข้อผิดพลาด 302/timeout ซึ่งเป็นพฤติกรรมของ Apps Script ระบบยังรับข้อความได้
4. หลัง Deploy ระบบจะนำเข้าฐานข้อมูลกฎหมายฉบับใหม่เองทุก 10 นาทีจนครบ
   - จากนั้นงาน `pruneTick` (ทุกชั่วโมง) จะลบมาตราที่ไม่มีในฐานข้อมูลฉบับใหม่ เช่น มาตราที่เปลี่ยนเลข หรือมาตราของกฎหมายอื่นที่ติดมา

### การแจ้งเตือนทาง LINE
- **ผู้ดูแลระบบ:** เมื่อมีผู้สมัครใหม่ ระบบส่งข้อมูลครบทุกช่องที่ผู้สมัครกรอก (เหมือนเวอร์ชัน 7) ยกเว้นรหัสผ่านทุกชั้นและคำตอบกู้คืนบัญชี ซึ่งไม่ส่งเด็ดขาด
- **สมาชิกแต่ละคน:** ตั้งค่าได้ที่ โปรไฟล์ › การแจ้งเตือนทาง LINE
  1. กด “เพิ่มเพื่อน LINE”
  2. กด “รับรหัสเชื่อมต่อ”
  3. ส่งข้อความ `เชื่อมต่อ <เบอร์โทรศัพท์> <รหัส 6 หลัก>` ในแชต
     - ระบบตรวจว่าเบอร์ตรงกับเบอร์ที่สมัครไว้
     - ถ้าตรง ระบบจะตอบกลับพร้อมรายละเอียดบัญชี
- **ทุกครั้งที่เข้าสู่ระบบสำเร็จ:** ระบบส่งข้อความ “เข้าสู่ระบบสำเร็จ” พร้อมกันถึงสมาชิกคนนั้นและผู้ดูแลระบบ
  - ข้อความระบุชื่อผู้ใช้ วันเวลา อุปกรณ์ และตำแหน่งโดยประมาณ
  - ถ้าไม่ต้องการให้ผู้ดูแลได้รับแจ้งทุกครั้ง ให้ตั้ง `LINE_ADMIN_LOGIN` = `0`
- **เปลี่ยนเบอร์โทรศัพท์:** ถ้าสมาชิกเปลี่ยนเบอร์ในโปรไฟล์ ระบบจะยกเลิกการเชื่อมต่อ LINE เดิม เพราะเบอร์ต้องตรงกันเสมอ
- **โควตาข้อความ:** LINE OA แพ็กเกจฟรีส่งได้ 300 ข้อความต่อเดือน การส่งถึงหลายคนนับรายคน
  - ข้อความตอบกลับ (เช่น ตอนเชื่อมต่อสำเร็จ) ไม่นับโควตา
  - ถ้าโควตาหมด การส่งจะไม่สำเร็จจนถึงเดือนถัดไป แต่การสมัครและการเข้าสู่ระบบยังทำงานตามปกติ
- **ข้อจำกัด:** LINE ไม่เปิดเผยเบอร์โทรศัพท์ของผู้ใช้ผ่าน API ระบบจึงยืนยันเบอร์ด้วยรหัส 6 หลักที่ได้จากหน้าโปรไฟล์หลังเข้าสู่ระบบแล้ว

### หน้าสมัครสมาชิกและหน้าเข้าสู่ระบบ
- **หน้าสมัครสมาชิก:** ขั้นตอนที่ 1 มีช่อง “หมายเลขโทรศัพท์” (จำเป็น)
- **หน้าเข้าสู่ระบบ:** แสดงเบอร์ที่กรอกตอนสมัครแบบแก้ไขไม่ได้
  - หลังเข้าสู่ระบบแล้ว แก้ไขเบอร์ได้ที่ โปรไฟล์ › แก้ไขข้อมูล
  - เบอร์จะแสดงบนอุปกรณ์ที่ใช้สมัครหรือเคยเข้าสู่ระบบแล้วเท่านั้น
  - ระบบไม่ดึงเบอร์จากเซิร์ฟเวอร์ตามชื่อผู้ใช้ เพื่อไม่ให้ผู้อื่นสุ่มดูเบอร์ของสมาชิกได้

### จุดเชื่อมต่อสำหรับระบบหลังบ้าน
- **ส่งข้อความถึงสมาชิก (วิธีเดิมของหลังบ้าน):** เพิ่มรายการใน `UserData.notices` (id ขึ้นต้น `MSG-`) — สมาชิกเห็นภายใน ~2 วินาที · ลบรายการออก = ซ่อนฝั่งสมาชิก
- **แชทจากสมาชิก:** บันทึก 3 ที่
  - ชีต `Chat` (เว็บไซต์หลัก)
  - ชีต `Reports` ประเภท “แชทกับผู้ดูแลระบบ” (รวมเป็นเรื่องเดียวต่อ 30 นาที)
  - Sheet1 ของระบบหลังบ้าน (sender = `member`)
- **ตอบแชท:** แถวใน Sheet1 ของหลังบ้าน (sender = `admin`, memberId ตรงกัน) หรือข้อความ `MSG-` ใน UserData แสดงในหน้าแชทภายใน ~2 วินาที
- **บล็อก:** ตั้ง `Members.blocked` เป็น “บล็อก” และใส่เหตุผลในคอลัมน์ “เหตุผลการบล็อก” (blockReason) · ตั้งกลับเป็น “ปกติ” = สมาชิกกลับมาใช้งานได้เองภายใน ~3 วินาที
- **ปิดปรับปรุง:** `Config.MAINTENANCE` on/off + `MAINTENANCE_MESSAGE` (บรรทัด “สาเหตุ:” “ปิดใช้งานตั้งแต่:” “คาดว่าจะเปิดใช้งาน:” “ข้อกฎหมายที่เกี่ยวข้อง:” “ติดต่อผู้ดูแลระบบ:” แยกเป็นหัวข้อให้อัตโนมัติ) — มีผลภายใน ~2 วินาที (เดิม 60 วินาที)
- **จำนวนผู้ใช้งานจริง:** อ่าน `Config.ONLINE_NOW` หรือเรียก `…/exec?api=online&k=<คีย์>`
  - ระบบหลังบ้านปัจจุบันนับจาก `lastSeen` ภายใน `onlineMinutes` = 5 นาที (ค่าใน ADMIN_SETTINGS) จึงลดช้ากว่าความจริงได้สูงสุด 5 นาที
  - แนะนำให้ตั้ง onlineMinutes = 1 และ pollSeconds = 5 ในหน้าตั้งค่าหลังบ้าน หรือให้หลังบ้านอ่าน `ONLINE_NOW`
- **ข้อมูลกฎหมาย (สาธารณะ อ่านอย่างเดียว):**
  - `…/exec?api=stats` — จำนวนไทย/ต่างประเทศ/รวม + ลิงก์ฐานข้อมูล
  - `…/exec?api=laws&offset=0&limit=500&q=` — รายชื่อกฎหมาย
  - `…/exec?api=law&id=K01` — ตัวบทรายมาตรา
  - `Config.LAW_COUNTS` อัปเดตทุกชั่วโมง

### ข้อจำกัดที่ต้องทราบ (ตามข้อเท็จจริง)
- **Google Sheets จำกัด 10,000,000 เซลล์ต่อไฟล์ ขยายไม่ได้** (เป็นข้อกำหนดของ Google ไม่ใช่การตั้งค่า)
  - ตัวบททั้งหมด 18.5 ล้านมาตรา (ไทย + ต่างประเทศ) ใส่ในชีตเดียวไม่ได้
  - จึงให้ระบบหลังบ้านเข้าถึงผ่าน API และลิงก์ฐานข้อมูลแทน
- **เอกสารภาษาลาวที่ใช้ฟอนต์รุ่นเก่า (ไม่ใช่ Unicode):** แหล่งต้นทางบันทึกเป็นสัญลักษณ์ ไม่มีตารางแปลงที่ถูกต้องแน่นอน ระบบจึงไม่แสดงสัญลักษณ์ (ไม่เดาข้อความ) และให้ลิงก์ต้นฉบับ

### สถานะผู้ใช้งานแบบเรียลไทม์ (รูปแบบใหม่ ใช้กับทั้งผู้ทดลองใช้งานและสมาชิก)
- **แสดงทันที:** เมื่อกดยอมรับ (ผู้ทดลอง) หรือเข้าสู่ระบบ (สมาชิก)
  - ทดสอบแล้ว: ผู้ทดลองถึงหลังบ้านใน 0.6 วินาที · สมาชิกแสดง “กำลังใช้งาน” ภายใน 3 วินาที
- **คงอยู่ตราบที่ยังเปิดหน้าเว็บไซต์:** ไม่ต้องแตะ เลื่อน หรือกดปุ่มใด
  - สลับไปแอปอื่นชั่วคราวยังนับว่าอยู่บนเว็บไซต์
  - ผู้ทดลองส่งสถานะทุก 10 วินาที · สมาชิกทุก 2 วินาที (เบื้องหลังทุก 15 วินาที)
- **ออกจากหน้าเว็บไซต์ (ปิดแท็บ/ปิดหน้า):** ส่งสัญญาณแบบ beacon ที่ส่งได้แม้หน้ากำลังปิด แล้วหายจากรายชื่อทันที
- **รหัสผู้ทดลองใช้งาน:** สร้างอัตโนมัติด้วยการสุ่มแบบเข้ารหัส รูปแบบ `G-` ตามด้วย 20 ตัวอักษร ไม่ซ้ำกันในแต่ละอุปกรณ์
  - แสดงให้ผู้ทดลองเห็นในป๊อปอัปและหน้านับถอยหลัง
- **ข้อมูลอุปกรณ์จริง:** ประเภทอุปกรณ์ ระบบปฏิบัติการ เบราว์เซอร์ ขนาดหน้าจอ ภาษา และ IP
- **ตำแหน่งจริง:** หลังกดยอมรับ ระบบขออนุญาตตำแหน่งของอุปกรณ์ แล้วบันทึกพิกัดและชื่อพื้นที่ (เขต/จังหวัด)
  - หากไม่อนุญาต ใช้ตำแหน่งโดยประมาณจาก IP
- **ชีต:** ข้อมูลบันทึกลงชีต Config แถว `GUEST_NOW` (ผู้ทดลอง) และชีต Sessions (สมาชิก) ในรูปแบบเดียวกับที่ระบบหลังบ้านอ่าน
  - `GUEST_NOW` อัปเดตอย่างน้อยทุก 10 วินาที

### วิธีอัปเกรด
1. วาง `Code.gs` และ `Index.html` ทับของเดิม แล้ว Deploy เป็น New version
2. **Supabase (สำเนาข้อมูลทุกชีต รวมสมาชิก):** โปรเจกต์ `deevvykxfvcadextxfby` (https://deevvykxfvcadextxfby.supabase.co) สร้างตารางครบแล้ว
   - (ไม่บังคับ) `SUPABASE_URL` — ค่าเริ่มต้นคือโปรเจกต์นี้อยู่แล้ว
   - Script Properties › เพิ่ม `SUPABASE_SERVICE_KEY` = คีย์ `service_role` จาก Supabase › Project Settings › API Keys (ห้ามเผยแพร่)
   - เลือกฟังก์ชัน `installSupabaseSync` › Run (ซิงก์ทันที และทุก 10 นาที) · ตรวจสถานะด้วย `supabaseStatus`
   - ทุกตารางเปิด RLS และไม่มีสิทธิ์สาธารณะ อ่าน/เขียนได้เฉพาะฝั่งเซิร์ฟเวอร์
3. **คำอธิบายกฎหมายรายมาตรา:** Script Properties › เพิ่ม `GEMINI_API_KEY` (จาก aistudio.google.com) · จำกัดจำนวนสร้างใหม่ต่อวันด้วย `EXPLAIN_DAILY` (ค่าเริ่มต้น 3000)
   - รัน `installExplainPrebuild` หนึ่งครั้ง ระบบจะสร้างคำอธิบายล่วงหน้า **ทุกมาตรา ทีละมาตรา** ของรัฐธรรมนูญ 2560 (279 มาตรา) และประมวลกฎหมายทั้ง 8 ฉบับ (รวมประมาณ 4,000 มาตรา) ทุก 10 นาที ทำต่อจากจุดเดิมเสมอ จนครบ
   - มาตราที่ยังไม่ได้สร้างล่วงหน้า ระบบสร้างให้ทันทีเมื่อผู้ใช้เปิด แล้วเก็บไว้ในชีต `Explain` (เปิดซ้ำไม่สร้างใหม่) · ผู้ดูแลตรวจทานได้ที่คอลัมน์ `reviewed`
4. **Vercel:** ไฟล์อยู่ในโฟลเดอร์ `vercel/` (ดูหัวข้อ Vercel ด้านล่าง)
